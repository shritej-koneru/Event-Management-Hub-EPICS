# Database Guide

## Setup

No system PostgreSQL is required for development. The server starts a **real**
PostgreSQL cluster via the `embedded-postgres` devDependency when `DATABASE_URL`
is empty.

```bash
cd server
npm install
npm run setup    # writes .env with a random JWT_SECRET
npm start        # ensure DB → migrate → seed → listen
```

Production must set `DATABASE_URL` (embedded PG is never used when that is set
and `NODE_ENV=production`).

## Environment variables (placeholder names only)

| Variable | Typical dev default | Notes |
| --- | --- | --- |
| `DATABASE_URL` | *(empty)* | Empty ⇒ embedded cluster |
| `USE_EMBEDDED_PG` | `true` | Dev/test only |
| `EMBEDDED_PG_PORT` | `5433` | Avoids clash with system PG on 5432 |
| `EMBEDDED_PG_USER` | `emh` | |
| `EMBEDDED_PG_PASSWORD` | *(set in .env)* | Never commit real values |
| `EMBEDDED_PG_DATABASE` | `emh` | Tests use `emh_test` |
| `EMBEDDED_PG_DIR` | `<server>/data/pg` | Gitignored cluster files |
| `JWT_SECRET` | *(required)* | Generated by `npm run setup` |

`.env` is gitignored. `.env.example` lists names only.

## Schema (after migration 005)

| Table | Role |
| --- | --- |
| `venues` | 14 campus graph nodes (id, name, map_x, map_y canvas fractions) |
| `venue_edges` | Stored walk graph, one row per undirected edge (`from_id < to_id`) |
| `events` | Catalogue; `venue_id` FK → venues; capacity CHECK |
| `users` | `id text` PK, email unique, password_hash, interests jsonb |
| `bookmarks` | PK `(user_id, event_id)` — personalization signal |
| `search_history` | Recent queries; pruned to newest 50 per user on write |
| `announcements` | BitChat event-relay log; `UNIQUE (room, message)`; `event_id` FK |
| `chat_messages` | Interactive chat; author, optional user/room FKs, bot flag |
| `migrations` | Ledger of applied `*.sql` filenames |

Relationships:

- `events.venue_id` → `venues.id` (required)
- `venue_edges.from_id` → `venues.id`, `venue_edges.to_id` → `venues.id`
- `bookmarks.user_id` → `users.id`, `bookmarks.event_id` → `events.id`
- `announcements.room` → `venues.id`, `announcements.event_id` → `events.id` (nullable)
- `chat_messages.user_id` → `users.id` (nullable), `chat_messages.room` → `venues.id` (nullable)

## Migration order

Applied in filename sort order; each file is one transaction:

1. `001_init.sql` — venues, events, users, bookmarks, search_history, announcements
2. `002_integrity_and_retention.sql` — announcements.room FK, search index + prune fn
3. `003_announcements_event_id.sql` — announcements.event_id column + index
4. `004_chat_messages.sql` — chat_messages table + indexes
5. `005_venue_map.sql` — venues.map_x/map_y + venue_edges (stored walk graph)

Migrations run automatically on every boot and are idempotent.

## Seed data

`npm run db:seed` (also runs on `npm start`):

- 14 venues matching the navigation graph
- 12 demo events across venues/dates/categories
- Demo user `alice@uni.edu` (password documented in README for local demo only)
- Sample announcements tied to real events

Re-seeding is safe (`ON CONFLICT DO NOTHING` / insert-if-missing).

## Commands

```bash
npm run db:migrate     # apply pending migrations only
npm run db:seed        # idempotent seed
npm run db:reset       # dropAll → migrate → seed (DESTROYS DATA)
npm run db:schema      # regenerate src/db/schema/schema.sql from live DB
npm test               # vitest against emh_test (embedded)
npm run verify:migrations  # cold-build a scratch DB from SQL files alone
```

Inspect (with embedded PG running):

```bash
psql "postgres://emh:<password>@127.0.0.1:5433/emh" -c '\dt'
psql "postgres://emh:<password>@127.0.0.1:5433/emh" -c 'SELECT count(*) FROM events;'
```

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Port 5433 in use | Another embedded cluster or leftover node | Stop old `node src/server.js`; retry |
| Encoding error on seed (Windows) | Cluster not UTF-8 | Delete `data/pg`, re-run `npm start` |
| Migration failed | Manual schema drift | `npm run db:reset` in dev only |
| `DATABASE_URL` refused in production | Missing URL | Set a real Postgres URL |
| Tests fail to boot PG | Port 5433 held by dev server | Stop the server before `npm test` |
| `dropAll` left a table | New table not listed in `migrate.js` | Add it to the DROP list |

Never point `db:reset` or `verify:migrations` at a shared production database.
The verifier refuses protected names (`emh`, `emh_test`, `postgres`, …).
